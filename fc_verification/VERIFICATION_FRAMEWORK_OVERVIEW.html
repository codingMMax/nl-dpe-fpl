1. Verification Philosophy

1.1 Independence Invariant

Four code paths must remain decoupled to avoid tautological “verification”:

  1. Architecture configuration — JSON in nl_dpe/dpe_*.json. Single source of truth.
  2. Generator — Python emitter that reads the JSON and writes RTL.
  3. Oracle — Python reference (numpy) that emits expected outputs and cycle counts from first principles. Never reads RTL or sim code.
  4. DUT — generator-emitted Verilog compiled under iverilog.

The TB consumes (3) via $readmemh of .mem artifacts and the DUT via instantiation, then compares.

1.2 No Circular Validation (Option A Rollback + Task #99 double-buffered LOAD)

  • Oracle formula: T_steady = max(LCYC, CCYC, OCYC) (Task #99)
  • RTL: emerges from physical bit-counter advances + ping-pong substrate selector. No COMPUTE_CYCLES parameter.
  • Faithful primitive fidelity: 0% bit-exact — oracle and RTL agree across all M values.
  • Workload fidelity: per-stage decomposed (nba + tree + clb + wrap) paid once in T_fill; T_steady is bit-exact. Concrete deltas refreshed post #99 re-run.

1.3 Modeling Honesty (Task #93 then Task #99)

The pre-Task-#93 design used a 4-slot ring buffer (a simulation convenience). Task #93 rewrote the faithful primitives to single-substrate slice-major storage with a load_safe LOAD-gate, exposing a +PRECISION per-pass cost. Task #99 then added a second physical input substrate (ping-pong A/B via load_phase), eliminating the WAR hazard that forced the LOAD-gate. The cycle cost reduces to T_steady = max(LCYC, CCYC, OCYC); the area cost is one extra PRECISION×R input buffer per DPE (already in the arch budget).

Why this matters: a circular validation produces 0% fidelity by construction. Our 0% on the faithful primitive is bit-exact across all 12 test modes including all 4 M-sweep values — the formula matches the RTL because both honestly model the silicon, not because they share a parameter.

5. Layer 1 — Component Roles (Post Task #99)

Generator (gen_dpe_*_faithful.py)

Reads per-arch JSON, emits a Verilog file with double-buffered slice-major storage (substrates A/B + load_phase selector) and corner-turn LOAD. Hard-codes topology (number of stages, ACAM presence); parameterizes dimensions (R, C, BUF, PRECISION).

Oracle (*_mac_oracle.py)

Pure-numpy reference. Three exported entry points:

  • signed_int8_mac(weights_2d, inputs_1d) → int32_vec — direct dot product.
  • bit_serial_signed_mac(...) — bit-serial reference with MSB-subtract (cross-checks signed_int8_mac).
  • expected_total_cycles(...) — closed-form T_fill + (M-1) · T_steady with T_steady = max(LCYC, CCYC, OCYC) (Task #99).

DUT (dpe_*_faithful.v)

Three concurrent sub-FSMs (LOAD, COMPUTE, OUTPUT). Storage is double-buffered slice-major (Task #99):

  • input_buf_slice_a[0..PRECISION-1][0..R-1] and input_buf_slice_b[...] — two physically separate PRECISION×R bit-slice substrates
  • load_phase — 1-bit selector that ping-pongs LOAD writes between A and B
  • mac_acc[0..C-1] — single int32 accumulator bank (pass-tagged ring carries pass IDs)
  • acam_out[0..C-1] — single int32 output bank (NL only)

No load_safe register: pass-(k+1) LOAD writes substrate B while pass-k COMPUTE reads substrate A; substrates are physically separate, no WAR hazard. NL: 2-stage compute + 1-cycle ACAM. AL: 3-stage (crossbar → ADC → shift-add), no ACAM. Area cost: 2× input buffer per DPE.

Testbench (tb_dpe_*_faithful.v)

Loads vectors via $readmemh; drives w_buf_en back-to-back across passes (no gate poll required under Task #99); observes data_out; measures cycle stamps; emits T# PASS|FAIL.

Smoke Orchestrator

make faithful-smoke (7 NL modes) and make faithful-smoke-al (5 AL modes). Iterates over test modes, calls iverilog+vvp, parses stdout.

10. Storage Layout — Double-Buffered Slice-Major + Corner-Turn (Task #99)

Pre-Task-#93: 4-slot byte-major ring buffer

   input_buffer[QDEPTH=4][R]    --+
   mac_acc     [QDEPTH=4][C]      |    Simulation convenience.
   acam_out    [QDEPTH=4][C]    --+    NOT silicon-faithful.

Task #93 (superseded): single-substrate slice-major + LOAD-gate

   input_buf_slice[PRECISION][R]  --+   Single input substrate; required
   mac_acc        [C]               |   load_safe gate to prevent WAR;
   acam_out       [C]             --+   T_steady = max(LCYC + PRECISION, ...)

Task #99 (current): double-buffered slice-major + ping-pong

   input_buf_slice_a[PRECISION][R]  --+    Two physical input substrates
   input_buf_slice_b[PRECISION][R]    |    + 1-bit load_phase selector.
   mac_acc          [C]               |    LOAD writes substrate B while
   acam_out         [C]             --+    COMPUTE reads substrate A.
                                            T_steady = max(LCYC, CCYC, OCYC)

Corner-turn LOAD — fixed wire permutation (preserved across all revisions)

   BRAM delivers 40 bits = 5 bytes per cycle, byte-major.

   Per LOAD cycle k (writing the substrate selected by load_phase):
     for j in 0..ELEMS_PER_STROBE-1:                       (5 bytes per strobe for NL)
       for i_bit in 0..PRECISION-1:                        (8 bit positions)
         slice[load_phase][i_bit][k*EPS + j] <= data_in[j*8 + i_bit]

   This is pure wiring (40 input bits routed to 40 distinct slice cells).
   One shared address counter (k) and a 1-bit ping-pong selector. No decode logic.

What Task #99 gives you

  • Two input substrates (2 × PRECISION × R bit cells), one for LOAD-write, one for COMPUTE-read each pass.
  • No WAR hazard: pass-(k+1) LOAD and pass-k COMPUTE touch disjoint physical cells.
  • No load_safe gate; no wrapper-side inter-pass stall in fc_top.v.
  • Area cost: 2× input-buffer flops per DPE (e.g., 2048 flops for NL R=256, 4096 for AL R=512). In arch budget.
  • Cycle saving: PRECISION × (M-1) per workload vs Task #93 LOAD-gate.
  • BRAM stays byte-major (matches host data format and inter-layer activations).

11. Double-Buffered LOAD — Task #99 (Supersedes Task #93 LOAD-Gate)

The problem single substrate creates (Task #93 design)

With a single-substrate input buffer, pass-(k+1) LOAD writes to the SAME physical cells that pass-k COMPUTE is reading bit-by-bit across PRECISION cycles. Without a gate, pass-(k+1)'s writes would corrupt pass-k's reads at subsequent bit positions. Task #93 added a load_safe register to gate LOAD until pass-k's last bit-fire cycle; the architectural cost was +PRECISION per pass in T_steady.

The Task #99 fix: a second physical substrate + ping-pong selector

   reg load_phase;                            // 1-bit ping-pong selector

   // Reset
   load_phase <= 0;                           // LOAD targets substrate A first

   // Per LOAD pass commit (LOAD sub-FSM moves to next pass)
   if (load_pass_commit) begin
       load_phase <= ~load_phase;             // Flip target substrate
   end

   // LOAD sub-FSM (always free; no gating)
   if (w_buf_en) begin
       // Write to whichever substrate load_phase selects
       if (load_phase == 0)
           input_buf_slice_a[i_bit][addr] <= data_in[...];
       else
           input_buf_slice_b[i_bit][addr] <= data_in[...];
   end

   // COMPUTE sub-FSM reads from the OTHER substrate (pass-tagged ring)

Honest cycle cost

   Task #93 (single-substrate + LOAD-gate):
     T_steady = max(LCYC + PRECISION, CCYC, OCYC)   = 60  (NL), 264 (AL)

   Task #99 (double-buffered):
     T_steady = max(LCYC, CCYC, OCYC)               = 52  (NL), 256 (AL)

   Per-pass cycle saved by Task #99: PRECISION cycles (8 at INT8)
   Per-workload cycle saved: PRECISION × (M-1)
     e.g., M=8 batched FC: 56 cycles per DPE saved
     e.g., M=128 batched attention: 1016 cycles per DPE saved

Area cost (paid in exchange)

   Task #93 input buffer:     PRECISION × R bit cells per DPE
   Task #99 input buffer:   2 × PRECISION × R bit cells per DPE
                            ──────────────────────────────────
   Δ:                       + PRECISION × R extra flops per DPE
     NL  (R=256, P=8):  + 2048 flops per DPE
     AL  (R=512, P=8):  + 4096 flops per DPE

This area cost is already accounted for in the arch budget — the cycle-saving is paid for with the second substrate.

12. Data Hazard Eliminated by Double-Buffering (Task #99)

Task #93 problem (now retired): "Slice 0 is consumed at cycle 53, so why not let pass-(k+1) write to slice 0 at cycle 54?" The catch was corner-turn LOAD writes to all 8 slices simultaneously every cycle, so any pass-(k+1) write would corrupt pass-k slice reads at later cycles. Task #93 solved this with a load_safe gate, costing +PRECISION cycles per pass.

Task #99 solves it physically: pass-(k+1) writes to a different substrate. Substrate A and substrate B occupy distinct flops; there is no shared cell for the LOAD write and the COMPUTE read to race over.

Why double-buffering is the silicon-faithful fix

   The Task #93 hazard arose because LOAD and COMPUTE shared the same R × PRECISION
   bit cells. Two reasonable resolutions:

     (a) Serialise: gate LOAD until COMPUTE finishes consuming.  Cost: PRECISION
         cycles per pass in T_steady.                                  ← Task #93

     (b) Parallelise: provide two physically separate substrates.      ← Task #99
         Cost: PRECISION × R extra flops per DPE (the second substrate);
         no cycle penalty; T_steady = max(LCYC, CCYC, OCYC) regains its
         pipeline-overlap meaning unchanged from the lazy-ring-buffer era.

One-line summary. Slice 0 alone is free at cycle 54 only because pass-1 writes to a different chip of flops (substrate B) than the one pass-0 is still reading (substrate A). Corner-turn LOAD still writes all 8 slices simultaneously — but it writes them into substrate B, where pass-0 has no business reading.

15. Analytical Pipeline Cycle Formula (Unified, Task #98 + Task #99)

One formula at every layer — no additive constants

   T_fill        = LCYC + CCYC + OCYC                          architectural minimum

   T_steady      = max(LCYC, CCYC, OCYC)                       per-pass interval (M > 1)
                                ↑
                          Task #99 double-buffered LOAD:
                          pass-(k+1) writes substrate B while
                          pass-k COMPUTE reads substrate A,
                          so no LOAD-gate, no +PRECISION term.

   Total(M)      = T_fill + (M − 1) × T_steady                 M-pass total

No `+PRECISION` LOAD-gate term, no `+2` NBA handoffs, no `TREE_PIPE`, no `CLB_NEEDED`, no `+6` wrapper. Those cycles exist in real RTL; they are reported as per-stage deltas, not embedded in the formula.

                + registered handshake (not separately visible at workload boundary)

   tree  = ⌈log₂(V)⌉    CLB adder tree pipeline depth (V > 1 only)

   clb   = 1 if (V > 1) OR (act AND NOT has_acam) else 0
                Activation LUT cycle (post-tree)

   wrap  = 6 (constant)  Six structural registers in fc_top.v:
                +1 BRAM-read pipeline       +1 registered DPE handshake
                +1 sign-extend latch        +1 BRAM-write tap
                +1 in-BRAM register         +1 done-detect latch

   delta = nba + tree + clb + wrap   (always paid ONCE in T_fill;
                                       T_steady is bit-exact)

Sim formula is unified: T_fill = LCYC + CCYC + OCYC at every layer. All deltas (primitive +2, workload +6/+7/+8) are observed and documented per-stage, not embedded in the formula.
