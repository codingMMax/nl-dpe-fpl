Where an attention head's time and energy go

Two heads, the smallest and the largest of the DSE: JetFormer-150P (n 32, dmodel 64, d 32) and ViT-B/16 (n 256, dmodel 768, d 64); two arrays, 128 × 64 and 512 × 256; the DSE's fixed mapping. Numbers from the simulator; the closed forms below are checked against it on all 8 arrays (JetFormer-150P within 12 %, ViT-B/16 within 6 % on cycles, 0.1 %, 0.0 % on energy).

Reading the time diagram, step by step: JetFormer-150P at 128 × 64

  • The stream. The projections deliver one token every 21 cycles and end at cycle 683. Tiled QK converts each token's Q and K rows as it arrives, 8 cycles each, and is done 19 cycles after the last token. It never falls behind.
  • The wait. A score job needs all S queries of its run. Here S = n = 32, one run, so the first job needs the last token's query. It starts at cycle 711, 28 cycles after the stream ends. The keys of block 0 were ready at cycle 347 and waited.
  • The chain. Then block 0 passes through four stages in turn, each starting when the one before delivers: score job 711–827, tile read 752–856, EXP 867–1,003, PV job 961–1,076, rescale 1,014–1,119. Block 1 follows 111 cycles behind. With 2 blocks this is one pass through the pipeline, not a steady state.
  • The tails. The run ends with the log l read-out, the softmax sending each query's final normalizer to the accumulator, one row per cycle (36 cycles), and the normalization O = o / l, EXP passes over the accumulator's groups that emit the head's output (107 cycles).
  • Why the rescale blocks overlap and the PV jobs do not. The accumulator has two crossbar groups, an EXP group for the rescale and a LOG group for the o-carry, and its waits are per wave: block 1's rescale waves start on the EXP group while block 0's LOG waves are still on the LOG group. A PV job runs all its waves on the one PV farm in lock-step, so the next job starts only when the farm is free.
  • So the 596 cycles after the stream are one pipeline latency plus the tails. More crossbars in any stage would not shorten them: each stage is waiting for the one before, not working. A head with S < n, such as ViT-B/16 at 128 × 64 (S = 64), starts its first run after S tokens and overlaps the rest of the stream.

Highlights

The projections stream the tokens; tiled QK, the online softmax, tiled PV and the output rescale form one pipeline behind them, working in runs of S = min(n, I) queries and blocks of 16 keys. A run's QK can start once its S queries are projected, so short runs (small I) start early and overlap the stream; a run of S = n waits for every token.

A bigger array stretches the stream and lengthens the runs (ViT-B/16: 34 → 111 cycles per token; 4 runs → one, no overlap). The pipeline's work is the same on every array.

The stages, by the numbers

The farms (QK and PV) are 80–91 % of the energy; the projections and the softmax are the critical path.

The model

1. Symbols and the two primitives

  • \(n\) tokens, \(d_m\) model width, \(d\) head width. The array is \(R \times C\) and \(I = \min(R, C)\).
  • A run is \(S = \min(n, I)\) queries. There are \(N_{run} = n / S\) runs and \(N_{block} = n / B_{kv}\) key blocks, with \(B_{kv} = 16\).
  • A projection has \(V = \lceil d_m / R \rceil\) tiles.
  • A crossbar has one port. The port moves \(w = 5\) bytes per cycle. A pass runs \(P = 8\) bit-slices.
\[ \tau(r) = \max\!\Big(\Big\lceil \tfrac{r}{w} \Big\rceil + P,\ \Big\lceil \tfrac{C}{w} \Big\rceil + 1\Big), \qquad e_{pass}(r) = 0.17\,C + 0.00016\,RC + 0.015\,r + 0.010\,C\ \text{pJ}, \qquad e_{port}(r) = 0.0495\,\Big(\Big\lceil \tfrac{8r}{40} \Big\rceil + \Big\lceil \tfrac{8C}{40} \Big\rceil\Big)\ \text{pJ} \]
  • \(\tau(r)\) is the time of one pass that loads \(r\) rows. The rows come in through the port, then the bit-slices run, then the \(C\) columns drain. The drain overlaps the next load unless it is longer.
  • \(e_{pass}(r)\) is the energy of one pass. The whole array fires every time: the ACAM on every column, every cell. Only the input buffer follows the rows loaded.
  • \(e_{port}(r)\) is the energy of the pass's port words.
  • A conversion pass handles \(I\) values. A score costs \(d\) conversions.

2. Cycles per stage (one key block of \(S \times B_{kv}\) scores, on the stage's own crossbars)

\[ T_{projection\_token} = \tau(\min(d_m, R)), \qquad T_{projection\_stream} = \frac{n \cdot T_{projection\_token}}{P_{proj}} \]
  • A projection pass loads one token's \(\min(d_m, R)\) inputs. The \(V\) tiles load in parallel.
  • The three projections run in lock step. Each copy takes one token per \(T_{projection\_token}\) cycles.
\[ T_{QK} = \frac{S B_{kv} d}{I N_E}\,\tau(I), \qquad T_{PV} = \frac{S d B_{kv}}{I N_{EP}}\,\tau(I) \]
  • A block of QK needs \(S B_{kv} d\) conversions. Each pass converts \(I\) values. The \(N_E\) crossbars share the passes.
  • PV is the same with \(N_{EP}\) crossbars.
  • The adds and the trees are CLB logic. They keep up with the passes and add no cycles.
\[ T_{reader} = \Big\lceil \tfrac{S B_{kv}}{K_{reader}} \Big\rceil, \qquad T_{EXP} = \frac{S B_{kv}}{I N_{EXP}}\,\tau(I), \qquad T_{softmax\_latency} = T_{reader} + T_{EXP} + 2\,\tau(S) + \Big\lceil \tfrac{S}{w} \Big\rceil, \qquad T_{softmax} = \max\!\Big(T_{reader},\ \tfrac{T_{softmax\_latency}}{2}\Big) \]
  • The scores of a block enter the online softmax through one reader. The reader takes \(K_{reader}\) scores per cycle.
  • The EXP passes convert the block's scores on \(N_{EXP}\) crossbars.
  • The two carry passes update the running max and sum. They load \(S\) rows. The walk writes \(S\) values at \(w\) per cycle.
  • Blocks pipeline two deep in the softmax. So its period is the larger of the reader and half the block latency.
\[ W_{rescale} = \Big\lceil \frac{S d}{I N_{OC}} \Big\rceil, \qquad T_{output\_rescale} = \frac{T_{EXP} + T_{PV} + W_{rescale}\,\tau(I) + 2\,\tau(I)}{2} \]
  • The output rescale gives every output element a rescale pass and a LOG pass per block. \(N_{OC}\) crossbars take a wave of \(I\) elements each, so a kind needs \(W_{rescale}\) waves.
  • A block's rescale needs the block's row maxima from the softmax. Its LOG passes need the block's PV output. So one block goes through the EXP passes, the PV job, and the rescale waves in a chain.
  • The softmax hands the row maxima over through a ring that holds two blocks. The ring frees a slot when the rescale has read it. So the chain may take two block periods, and the period is half the chain.

3. Latency

\[ T_{block} = \max\big(T_{QK},\ T_{softmax},\ T_{EXP},\ T_{PV},\ T_{output\_rescale}\big) \]
  • The four core stages work on different blocks at the same time. Each has its own crossbars.
  • So the pipeline moves one block per \(T_{block}\), the slowest stage.
\[ T_{stream\_bound} = T_{projection\_stream} + \max(1, N_{run} - 1)\, N_{block}\, T_{block}, \qquad T_{core\_bound} = \frac{S \cdot T_{projection\_token}}{P_{proj}} + N_{run} N_{block}\, T_{block} \]
  • A run can start when its \(S\) queries are projected. Its blocks also need their keys, which the stream delivers in order.
  • If the stream is slower than the core, the first run follows the stream block by block. The other runs come after the stream, one after another. With one run, all of it comes after the stream.
  • If the core is slower, the stream waits for it. Then the first run starts after \(S\) tokens and every block takes \(T_{block}\).
  • The larger of the two bounds holds.
\[ T_{fill} = \lceil \log_2 V \rceil + 4 + 24, \qquad T_{first\_block} = N_{run}\,(T_{softmax\_latency} - T_{block}), \qquad T_{readout} = (N_{run} - 1)(S + 4), \qquad T_{tail} = T_{PV} + W_{rescale}\,\tau(I) \]
  • \(T_{fill}\): the projection output path and the first QK job.
  • \(T_{first\_block}\): a run's first block pays the full softmax latency. The others follow at the period.
  • \(T_{readout}\): a run ends by reading out its \(S\) log-sum values. The next run starts after that.
  • \(T_{tail}\): the last block still needs its PV job and the epilogue after the softmax is done.
\[ T_{head} = \max\big(T_{stream\_bound},\ T_{core\_bound}\big) + T_{fill} + T_{first\_block} + T_{readout} + T_{tail} \]

4. Energy per stage (pJ; \(e_{add} = 0.085\), \(e_{compare} = 0.264\), \(e_{memory} = 0.0495\) per 5 bytes)

\[ E_{projection} = 3Vn\,[e_{pass}(\min(d_m, R)) + e_{port}] + 3nd(V - 1)\,e_{add} \]
\[ E_{QK} = \Big(\tfrac{n^2 d}{I} + 2n\Big)[e_{pass}(I) + e_{port}] + (2n^2 d - n^2)\,e_{add} + n^2\,e_{compare} \]
\[ E_{softmax} = \Big(\tfrac{n^2}{I} + N_{run}(2N_{block} - 1)\Big)[e_{pass}(I) + e_{port}] + \tfrac{17}{8} n^2\,e_{add} + \tfrac{17}{16} n^2\,e_{compare} \]
\[ E_{PV} = \Big(\tfrac{n^2 d}{I} + n\Big)[e_{pass}(I) + e_{port}] + \Big(2n^2 d - \tfrac{n^2 d}{B_{kv}}\Big)e_{add} \]
\[ E_{output\_rescale} = \tfrac{2 n^2 d}{I B_{kv}}\,[e_{pass}(I) + e_{port}] + \tfrac{n^2 d}{8}\,e_{add} \]
\[ E_{memory} \approx \tfrac{e_{memory}}{5}\Big(3nd + \tfrac{2n^2 d}{B_{kv}} + \tfrac{2n^2 d}{S} + 4n^2 + \tfrac{7 n^2 d}{B_{kv}}\Big), \qquad E_{head} = E_{projection} + E_{QK} + E_{softmax} + E_{PV} + E_{output\_rescale} + E_{memory} \]
  • Each stage's energy is its passes times the pass price, plus its CLB work.
  • The passes are the work divided by \(I\). The price grows with \(C\) and with \(R C\). So the pass energy grows as fired cells per converted value, \(RC / I\).
  • The CLB adds and compares do not depend on the array. QK and PV each add about \(2 n^2 d\) times.
  • \(E_{memory}\) is the block-RAM traffic of the stages. It is about 1 % of the head.

5. Area per stage (\(A_{tile}(R, C)\) = the tile's grid cells × 66,117 MWTA × 0.033864 µm²; the row-parallel tile of experiment.md §5.1: 6 cells at 128 × 64, 36 at 512 × 256)

\[ A_{projection} = 3 P_{proj} V\, A_{tile}, \quad A_{QK} = (N_E + 2P_{proj})\, A_{tile}, \quad A_{softmax} = (N_{EXP} + 2)\, A_{tile}, \quad A_{PV} = (N_{EP} + P_{proj})\, A_{tile}, \quad A_{output\_rescale} = 2 N_{OC}\, A_{tile} \]
\[ A_{head} = A_{projection} + A_{QK} + A_{softmax} + A_{PV} + A_{output\_rescale} + A_{CLB}(I) + A_{memory} \]
  • Each stage's area is its crossbar count times one tile. The counts come from the mapping, not from the array.
  • The tile grows with the array. So the crossbar area grows with the array for the same work.
  • \(A_{CLB}(I)\) is the soft logic. It is head-level, from VTR. It grows with \(I\): 10.4k, 12.9k and 17.5k CLBs at \(I\) = 64, 128 and 256.
  • \(A_{memory}\) is the block RAM, also from VTR.

6. Our mapping

  • \(P_{proj} = 1\), \(N_E = N_{EP} = 2d\), \(N_{EXP} = 2\), \(N_{OC}\) by the floor rule (2 to 8), \(B_{kv} = 16\), \(S = \min(n, I)\), \(K_{reader} = 5\).
  • With these, \(T_{QK} = T_{PV} = T_{EXP}\) and \(T_{reader} = S B_{kv} / 5\). The output rescale's chain is the largest term on every array. So \(T_{block} = T_{output\_rescale}\).
  • The array enters the core only through \(S\) and \(\tau(I)\). It enters the stream through \(\min(d_m, R)\). It enters the energy through \(e_{pass} / I\). It enters the area through \(A_{tile}\) and \(A_{CLB}(I)\).

Sweeping the array: cycles, energy, area and their product

  • Cycles, JetFormer-150P. dmodel is 64, so a token never loads more than 64 rows. Time does not change with R. At every R ≥ C it is 1,279 cycles at C = 64, 1,532 at C = 128, 2,579 at C = 256. It grows with C, because every pass drains all C columns.
  • Cycles, ViT-B/16. dmodel is 768, so a token loads all R rows at every R of the grid. Time grows with R: 24,395 to 44,105 cycles at C = 64. C = 128 is the fastest at every R. After the projection stream ends, the core still has to finish the later runs, or the whole run when there is only one. That leftover is 13.1k cycles at C = 64 (4 runs, S = 64), 7.9k at C = 128 (2 runs, S = 128), 13.9k at C = 256 (1 run, S = 256). It is smallest at S = 128.
  • Energy. The CLB adds, compares and memory are the same at every array: JetFormer-150P 12.3 nJ of 31.8 nJ, ViT-B/16 1.54 µJ of 3.75 µJ at 128 × 64. The rest is the passes. A pass fires all R × C cells and drains all C columns for I converted values. So energy rises with R at every C once R ≥ C: JetFormer-150P 31.8 nJ to 36.9 nJ, ViT-B/16 3.75 µJ to 4.26 µJ at C = 64.
  • Area. The crossbar tiles scale with R × C, the CLB with I. Area rises with R and with C at both heads: JetFormer-150P 17.7 to 36.6 mm², ViT-B/16 34.6 to 74.3 mm² from 128 × 64 to 512 × 256.
  • Cycles × area. It rises with R and with C at every point. 128 × 64, the smallest array of the grid, is the best at both heads; 512 × 256 costs 4.2× (JetFormer-150P) and 4.0× (ViT-B/16). ViT-B/16's 128 × 128 is 9 % faster but 30 % larger, so its product is 1.19×. The DSE's ADP adds Fmax on top; its attention front is 128 × 64 alone.
  • Why. Attention uses an array as a port-fed converter. A projection pass loads min(dmodel, R) rows. A DIMM pass loads I = min(R, C) rows. Every pass fires all R × C cells and drains all C columns. Rows and columns beyond those cost area, energy and drain time, and save no time.
