Inside each operation: load, compute, read out

Every operation of the attention head runs as crossbar passes, and every pass has the same three stages. The boards and diagrams are the simulator's own passes for JetFormer-150P and ViT-B/16 on 128 × 64 and 512 × 256.

LoadThe input enters through the crossbar's 40-bit port, 5 numbers per cycle.numbers in ÷ 5 cycles
ComputeOne cycle per bit of the 8-bit input, plus 2 to finish. The same on every array.10 cycles
Read outThe output leaves through a 40-bit port, 5 numbers per cycle, over all C columns.C ÷ 5 cycles
  • How the stages overlap. The next pass starts loading as soon as the current pass has done its 8 bit cycles, so the read-out of one pass runs while the next pass loads and computes.
  • Which stage sets the pace. The longer side: load + 8, or read-out + 1. The shorter side is hidden. A wait (grey) is a pass held up by the other side or by its input.
  • What changes with the array. Load time follows the numbers a crossbar takes in, read-out time its column count C. Compute never changes.

Each operation, pass by pass

Each board is one crossbar group at work, cycle by cycle: the input port and buffer (load), the array with its 8 bit-slices (compute), the output buffer and port (read out). The label in each part says which pass is there, so you can see one pass reading out while the next one loads. Both arrays run on one clock, and the diagram under the boards marks the same cycle. The boards play the passes of the diagram, taken from the steady part of the head.

The full head, one key block

Every crossbar group of the attention core, with one key block's passes in colour and the other blocks faint. Each group is two strips: the top one is its input side (load, then compute), the bottom one its output side (read-out). The whole head with all of its crossbars animated is on the page Attention head in time.

The softmax of a block can start only after all of the block's QKᵀ passes, because it needs the block's maximum score. PV then follows the softmax pass by pass, and the rescale waits for both. While one block is in the softmax, a later block is already in QKᵀ: that is the latency hidden between operations.

  • 128 × 64. Block 2 takes 444 cycles from its first QKᵀ load to its last rescale read-out. While block 2 is in QKᵀ, block 1 is in softmax EXP.
  • 512 × 256. Block 2 takes 721 cycles from its first QKᵀ load to its last rescale read-out. While block 2 is in QKᵀ, block 1 is in softmax EXP.

When the core starts

Each crossbar group is two strips: the top strip is its input side (load, then compute), the bottom strip its output side (read-out). Where both strips of a group are busy at once, a read-out is hidden under the next pass's load.

  • On 128 × 64 one run holds all 32 queries, so the first QKᵀ pass needs the last token: the projection ends at cycle 687 and QKᵀ starts at 721. Nothing overlaps the projection.
  • On 512 × 256 one run holds all 32 queries, so the first QKᵀ pass needs the last token: the projection ends at cycle 1,718 and QKᵀ starts at 1,721. Nothing overlaps the projection.
  • The core can start only when a run's queries are ready, because each QKᵀ pass works on every query of the run at once. A run holds at most min(R, C) queries: the softmax updates one running max and sum per query row in a single crossbar pass.

When the core starts

Each crossbar group is two strips: the top strip is its input side (load, then compute), the bottom strip its output side (read-out). Where both strips of a group are busy at once, a read-out is hidden under the next pass's load.

  • On 128 × 64 a run holds 64 queries, so the head is 4 runs. The first run needs only tokens 1 to 64: QKᵀ starts at cycle 2,240 while the projection runs on to cycle 8,719. That is the overlap.
  • On 512 × 256 one run holds all 256 queries, so the first QKᵀ pass needs the last token: the projection ends at cycle 28,470 and QKᵀ starts at 28,486. Nothing overlaps the projection.
  • The core can start only when a run's queries are ready, because each QKᵀ pass works on every query of the run at once. A run holds at most min(R, C) queries: the softmax updates one running max and sum per query row in a single crossbar pass.
