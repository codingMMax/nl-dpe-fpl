The head

X enters the projection GEMMs; Q and K meet in the QK DIMM; the online softmax turns scores into log P; the PV DIMM weights V; the accumulator rescales and normalizes into O8. module · ip/gemm/rtl/sim/gemm_top.v · 389 lines · certified v2, unchanged except the out_valid port

Projection GEMM: gemm_top

Y = trunc8(X·W) for one token row per pass. In the head K = dm, N = d and H = 1 (d ≤ C), so a GEMM is V crossbars stacked over dm. A copy holds three (WQ, WK, WV) that run in lock-step on the same X burst; the head has Pproj copies.

Build sheet

  • for gc < P_PROJ three gemm_top (Q, K, V) per copy in the head netlist.
  • Derived: V = ⌈K/R⌉, H = ⌈N/C⌉, TREE_PIPE = log₂V.
  • for gv < V, gh < H one dpe per tile, REGULAR, extent ROWS_USED × COLS_USED.
  • Readiness: MSB_SA_Ready = AND of all tiles.
  • Drain phase: handshakes → marker pipeline.
  • Reduction tree: TREE_PIPE registered folds.
  • Serializer and lanes: data_out, out_valid.
  • Pass end: dpe_done, the reg_full busy flag.

Parameters here

Pproj multiplies the whole module (3 per copy). V is the number of crossbars per GEMM; it grows when dm > R, which is when more copies pay most.

module · ip/dimm/rtl/sim/dimm_tile_top.v · 1,200 lines · 7 modules · two instances

Tiled DIMM: dimm_tile_top

One job computes one tile C = A·B (or A·B⊤) in the log domain: every crossbar sums ±EXP(LA + LB) over its column k. The same module is the QK DIMM and the PV DIMM; switch the instance to see how the ports, loaders and output change. The farm is cut into slices of XS = 16 crossbars that run in lock-step.

Build sheet

  • Derived: I, NB, WK, NG, TW, LW, XS, NS, KS, AGRP, BGRP, widths.
  • Guards: powers of two, N ≤ I, M·N ≥ I, 2 ≤ K ≤ N_E, NG ≤ WK, NG ≤ XS, frame shapes.
  • §1 Streams: for gch < A_CH / B_CH a dimm_conv per int8 channel, then the distribution register.
  • §2 A loader control: transposer (row frame) or window stager (window frame).
  • §3 B loader control: transposer (TRANS_B 1) or row writer (TRANS_B 0).
  • §4 Slots, credits, jobs: the job register and the registered decision.
  • §5 Slices: for gs < NS A staging, B staging, dimm_slice.
  • dimm_slice: run state, engine, B and A memories, crossbars, slice tree.
  • for gf < XS per crossbar: feed, dpe EXP, sign ring, signed drain.
  • §6 Top tree, NARROW, for gi < NG output channels, done.
  • dimm_tile_ctrl, the window engine (v2 verbatim).
  • dimm_tree, the registered adder trees.

Parameters here

The farm size (NE, NEP) sets the slice count and the output channels; XS fixes what one slice is; the ports' channel counts come from Pproj (int8 operands) and NEXP (log P).

module · ip/softmax/rtl/sim/softmax_online_top.v · 1,597 lines · 10 modules

Online softmax: softmax_online_top

One run per start: S query rows over n keys in blocks of Bkv. Per block it finds the row max, emits log α and log P, sums the P values, and carries (m, log l) per row; at the end of the run it sends log l.

NEXP is the only crossbar count here besides the two carry crossbars. S_CH follows the QK DIMM's output groups; Bkv sets the block, and so the number of blocks per run.

module · ip/softmax/rtl/sim/softmax_online_acc.v · 597 lines · 2 modules

Accumulator: softmax_online_acc

The output half of the online softmax. Per block it rescales the running o by α and adds o_part (F6); per run it divides by l (F7). It holds (lo, so) per element as log magnitude plus sign, and reads the run's O8 rows out in token order.

Parameters here

NOC sets both groups (2·NOC crossbars) and the waves W. P_CH comes from the PV DIMM (NGPV = NEP/Bkv), which is why NEP = d collides with the floor-rule NOC.

module · top/rtl/sim/att_ctrl.v · 153 lines · the same file in both twins

Tiling controller: att_ctrl

The only attention-specific logic, and it is counters only: when each GEMM copy may take its next token, which jobs the two DIMMs run and in which order, when the softmax starts a run, and when the head is done.

Parameters here

att_ctrl has no area to speak of; its parameters only size counters. Its rules (the three staging credits) decide when the X stream may run.

The mapping space

A build is fixed by its shape (n, dm, d), its crossbar config (R, C) and its mapping; everything else is derived by formula inside the RTL. Measured effects come from the head model on the 432 DSE builds (4 PV B credits, 2026-10-15). Line numbers point into the simulation twins.
