# coffe_flow_22nm — TensorSlices-calibrated 22 nm COFFE flow

COFFE 2.0 **hard-block interface** evaluation (`-hi`) of the NL-DPE `dpe` block's **local input
crossbar** at 22 nm with the published TensorSlices COFFE constants. `-hi` zeroes the ReRAM/ACAM
core, so the reported number is the **local input crossbar + its one-hot select SRAM**
(integration footprint). C does not enter the COFFE area model (`num_gen_outputs` is never read),
so one measured run per R covers every C.

## Results files / simulator contract

Canonical CSVs (valid configs only, `C <= R`):

- `sweep_summary_full.csv` — row-parallel model (primary; 9 rows)
- `sweep_summary.csv` — proportional-bandwidth comparison (11 rows)

Authoritative columns (units: µm² unless noted):

| Column | Meaning |
|---|---|
| `R`, `C` | crossbar geometry |
| `n_in`, `n_out` | block interface pins (`n_out` is inert in COFFE) |
| `mux_implemented`, `sram_per_mux`, `muxes`, `crosspoints` | crossbar geometry |
| `bare_um2`, `sram_um2` | pass network / select-SRAM decomposition |
| **`total_um2`** | **local input crossbar + select SRAM (the COFFE result)** |
| `per_pin_um2`, `per_crosspoint_um2` | normalized costs |
| `logic_um2` | DPE logic area (`nl_dpe/area_power.py`, 22 nm) |
| `routing_um2`, `tile_total_um2` | SB/CB routing area and logic+routing tile total |
| **`logic_plus_xbar_um2`** | **DPE logic + local crossbar (block size, no fabric routing)** |
| `xbar_vs_logic_pct` | `total_um2 / logic_um2` |
| `load_cycles`, `drain_cycles` | bandwidth-model cadence |
| `l1_w`…`per_mux_um2` | sized widths / unit costs (provenance) |
| `run` | source run dir (`work/...`) |

Block-size formulas for the simulator:

```
logic + crossbar            = logic_plus_xbar_um2
logic + routing + crossbar  = tile_total_um2 + total_um2
```

The crossbar area depends only on R for a fixed model (`num_gen_outputs` is never read); C changes
only the logic/routing area. Provenance: COFFE pristine
`ecde3effd352e5b2ba89d17c1e4cbd620b369eca`, `ERF_MAX_ITERATIONS = 4`, `-a 1 -d 2 -hi 100`,
TensorSlices constants (MWTA = 33,864 nm²); calibration anchor `work/tensorslice` =
2,771.325 µm² (+0.0117% vs published 2,771).

## Launch

```bash
source /mnt/vault0/jiajunh5/set_cad.sh
bash run_dpe.sh <R> [fullr|bw]   # fullr default; creates work/<run>/ + config from the 47-pin seed
bash run_tensorslice.sh          # calibration anchor -> work/tensorslice/report.txt
python3 sweep_summary.py [fullr|bw]   # fullr -> sweep_summary_full.*, bw -> sweep_summary.*
```

Launchers run COFFE from the pristine clone
(`/mnt/vault0/jiajunh5/coffe_pristine` @ `ecde3effd352e5b2ba89d17c1e4cbd620b369eca`, unmodified,
`ERF_MAX_ITERATIONS = 4`) with `-a 1 -d 2 -hi 100` and write `launch.log` inside the run folder.
COFFE deletes only the *subdirectories* of the output folder and rewrites `report.txt`, so
`config.yaml`, `README.md` and `launch.log` survive a re-run. Requirement: `set_cad.sh`
environment (HSPICE W-2024.09-1).

**Naming constraint:** COFFE hard-block names are all-lowercase (`dpe_full_r<R>`, `dpe_r<R>`) —
HSPICE folds netlist/measure names to lowercase in `.lis` output while COFFE looks them up with
the configured case, so an uppercase name breaks the sizing. Directory names may use uppercase.

## Constants (published TensorSlices COFFE artifact)

Source: `https://github.com/aman26kbm/COFFE`, branch `amana_modif`,
`input_files/matmul_8x8int8_4x4fp16_45nm/{coffe_fpga.txt,matmul.txt}` (same constants family as
the TensorSlices papers, TRETS 2022 DOI 10.1145/3529650 / FPGA'21).

| Group | Values |
|---|---|
| Fabric | N=10, K=6, W=320, L=4, I=60, Fs=3, Fcin=0.15, Fcout=0.10, Or=2, Ofb=2, Fclocal=0.5, Rsel=c, Rfb=c |
| Device/process | bulk, pass_transistor, vdd=0.8, vsram=1.0, vsram_n=0.0, gate_length=22, rest_length_factor=1, min_tran_width=45, trans_diffusion_length=52, **min_width_tran_area=33864 nm²**, sram_cell_area=4 |
| SPICE model | `spice_models/ptm_22nm_bulk_hp.l` / `22NM_BULK_HP` |
| Metal | 4 layers: (0.054825,0.000175), (0.007862,0.000215), (0.029240,0.000139), (0.227273,0.0) |
| Hard-block knobs | `crossbar_modelling=optimistic` (parsed but unused by COFFE), `soft_logic_per_block=4`, `input_usage=0.8`, area/freq/power scale factors 0.21/1.33/0.22 |
| Cost / interface | `-a 1 -d 2` (`cost = area^1 × delay^2`), `-hi 100` (loose interface bound; interface-only sizing, core = 0) |

All configs: `crossbar_population = 0.50`, `num_crossbars = 1`, `num_dedicated_outputs = 0`.
`min_width_tran_area` equals the MWTA unit of `nl_dpe/area_power.py` (0.033864 µm²/MWTA).
Inert keys (`height: 16`, `clock_period: [3.0]`, `area_cost_exp: 1.0`, `num_gen_outputs`) are
unified to the artifact values so any two configs differ only in block identity and output paths.

## Caveats

- Under `-hi`, **only the hard-block interface is sized**; the soft-tile numbers in each report
  (SB/CB/local-mux/LUT rows, `Tile` area) use COFFE's **default transistor sizes**, not optimized
  ones — the CLB local mux is an unsized reference, not an optimized comparator.
- Upstream COFFE's hard-block local-mux **area model counts the restorer and the driver's first
  stage (`inv_1`) but not the second stage (`inv_2`)** (`coffe/mux_subcircuits.py:_generate_ptran_driver`,
  `coffe/fpga.py:_HBLocalMUX.update_area`). The published 2,771 µm² uses the same code path.
- The ReRAM/ACAM core is not modeled (`Core area: 0.0`); the DPE logic area per (R,C) comes from
  `nl_dpe/area_power.py`.
- `logs/` holds historical evidence from earlier layouts (tags `dpe22_p050`, `tsmatch_cal`);
  raw pre-alignment evidence is in `logs/sep_30/`.
- All measured runs (both families) converged to **identical area-counted transistor widths**
  (pass W=1, restorer W=1, inv_1 nmos 2 / pmos 1), so bare area = `n·[(impl+L2+1)·0.966 + 2.4503]`
  MWTA exactly and SRAM = `n·(L1+L2)·4·MWTA` (asserted per run by `sweep_summary.py`).
